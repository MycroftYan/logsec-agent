# 实测记录：case_010 可疑行为分析

一次完整的 ReAct 对话，用于演示"智能体自己决定查什么"。原始终端输出见同目录 [`demo-case010.log`](demo-case010.log)。

| 项目 | 内容 |
|---|---|
| 日期 | 2026-11-18 |
| 环境 | Windows 11、Python 3.11.5、AgentScope 2.0.12 |
| 模型 | `deepseek-flash` |
| 命令 | `python ask.py "case_010 里发生了什么可疑行为？请给出证据"` |
| 结果 | 11 次工具调用，输入 27,441 / 输出 2,828 token，正常结束 |

## 智能体自己决定的 11 次工具调用

| # | 工具 | 参数 | 为什么调它 |
|---|---|---|---|
| 1 | `list_cases` | 翻第 0 页 | 先看有哪些案件 |
| 2 | `search_events` | `case_id=case_010` | 列出该案件的全部 7 条事件 |
| 3 | `get_event` | `E02100` | 看"安全日志被清除"这条的细节 |
| 4 | `get_event` | `E02102` | 看 Administrator 远程登录的来源 |
| 5 | `get_event` | `E02104` | 看密码重置的目标与主体 |
| 6 | `get_event` | `E02106` | 看机器账户的 Kerberos 登录 |
| 7 | `get_event` | `E02101` | 补上凭据验证成功这条 |
| 8 | `get_event` | `E02103` | 看 IPC$ → samr 远程枚举 |
| 9 | `get_event` | `E02105` | 看 IPC$ → lsarpc 远程枚举 |
| 10 | `search_events` | `keyword=172.16.66.37` | 顺着来源 IP 查整个库里还有谁被它访问过 |
| 11 | `search_events` | `keyword=02694W-WIN10` | 顺着来源主机确认它是不是跳板 |

第 10、11 步不是我们要求的：模型自己判断"这个 IP 值得跨案件再查一次"，然后带出了 case_022、case_147 的旁证。这就是 ReAct 循环和"固定流程脚本"的区别。

## 回答（节选）

> **结论**：case_010（主机 01566s-win16-ir.threebeesco.com，2020-09-17 10:57:37–10:57:53）记录了一段典型的"先清除日志、再做远程凭据操作"的可疑序列，7 条事件高度集中在这一分钟内：
>
> 1. **安全日志被清除**：10:57:37，Security 1102，操作主体 `3B\a-jbrown` [E02100]。
> 2. **紧接着来自内网的 Administrator 远程登录**：10:57:44，Security 4624 网络登录（LogonType=3，NTLM），来源 **172.16.66.37 / 02694W-WIN10** [E02102, E02101]。
> 3. **通过 IPC$ 做 SAMR / LSARPC 远程枚举**：5145 访问 `samr`、`lsarpc`，是该类账户发现工具的典型痕迹 [E02103, E02105]。
> 4. **尝试重置计算机账户密码**：4724，以 `3B\Administrator` 为主体改本机机器账户 `01566S-WIN16-IR$` 的口令 [E02104]。
> 5. **随后机器账户本地 Kerberos 登录**：10:57:53，来自 `::1` [E02106]。
>
> **无法确定的部分**：本案件没有 Sysmon 进程创建日志，因此**不能**断定攻击者具体用了哪个工具（net.exe / BloodHound / PsExec 都只是可能手段）；1102 只能说明日志被谁的账号清空，不能确定该账号是否被盗用；4724 只是"尝试重置"，日志没有证明成功。

## 这次对话说明了什么

- **每条结论都挂 uid**：回答里 `[E02100]`、`[E02102]` 这样的编号都能用 `get_event` 复核，这是第 6 周要做的"证据校验"的输入。
- **会主动说不确定**：模型明确指出"没有进程创建日志，不能断定用了什么工具"，没有编造命令行。这一点正是评测里"证据有效率"要量化验证的。
- **成本可控**：一题 2.7 万输入 token，按 `deepseek-flash` 价格约合几分钱；第 7 周做 20–30 题评测的总成本可以忽略。
- **工具太少会拖累它**：第 10、11 步是两个"翻遍全库关键字"的调用。等第 3 周加上 `count_events` 和 `get_event_context` 之后，这类问题可以直接统计出结果，不用一页页翻。
