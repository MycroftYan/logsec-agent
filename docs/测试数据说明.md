# 测试数据说明

这个文件夹是日志安全分析智能体的输入数据。三份数据都来自公开仓库，2026-11-17 下载，没有改动原文件内容。

## 1 目录

```text
测试数据/
├── README.md                                  本说明
├── 1_Windows攻击日志_EVTX-ATTACK-SAMPLES/
│   └── evtx_data.csv                          主数据
├── 2_SSH登录日志_Loghub-OpenSSH/

├── 3_APT-Hunter检测结果样例/

```

## 2 三份数据各是什么

| 数据 | 来源 | 规模 | 在项目里的用途 |
|---|---|---|---|
| `evtx_data.csv` | GitHub 仓库 `sbousseaden/EVTX-ATTACK-SAMPLES` | 4,633 条 Windows 事件，326 列，来自 249 个日志文件、19 台主机，覆盖 8 种 ATT&CK 战术 | 主数据。每个日志文件当作一个案件 |
| `OpenSSH_2k.log` | GitHub 仓库 `logpai/loghub` | 2,000 行 Linux sshd 日志，时间是某年 12 月 10 日 06:55 到 11:04，主机名 LabSZ | 入门演示。内容直观，适合讲解 |
| `Sample_TimeSketch.csv` | GitHub 仓库 `ahmedkhlief/APT-Hunter` 的 `Samples/` | 891 条告警，11 列 | 可选。它是课程给定系统 APT-Hunter 的检测结果样例 |

### 2.1 主数据：Windows 攻击日志

每一行是一条 Windows 事件。列很多但很稀疏，不同类型的事件只填其中一部分列。

常用的列：

| 列名 | 含义 |
|---|---|
| `EVTX_FileName` | 这条事件来自哪个日志文件。**文件名里常直接写着攻击技术，属于标准答案** |
| `EVTX_Tactic` | 这个日志文件对应的 ATT&CK 战术。**属于标准答案** |
| `EventID` | 事件类型编号，例如 4624 是登录成功，Sysmon 的 1 是进程创建 |
| `Channel` | 日志通道，例如 `Security`、`Microsoft-Windows-Sysmon/Operational` |
| `Computer` | 主机名 |
| `SystemTime` | 事件时间，范围从 2017-06-09 到 2021-06-09 |
| `CommandLine`、`Image` | 进程的命令行和程序路径，只有进程类事件才有 |
| `IpAddress`、`TargetUserName` | 来源地址和目标账号，只有登录类事件才有 |

按战术分的事件数（合计 4,633）：

| 战术 | 事件数 |
|---|---|
| 横向移动 Lateral Movement | 1,288 |
| 权限提升 Privilege Escalation | 1,088 |
| 执行 Execution | 533 |
| 命令与控制 Command and Control | 432 |
| 防御规避 Defense Evasion | 431 |
| 持久化 Persistence | 411 |
| 凭据访问 Credential Access | 283 |
| 发现 Discovery | 167 |

每个日志文件只对应一种战术。文件大小差别很大：最少 1 条事件，中位数 5 条，最多 869 条。

### 2.2 入门数据：SSH 登录日志

每一行是一条 sshd 日志，例如：

```text
Dec 10 06:55:46 LabSZ sshd[24200]: Invalid user webmaster from 173.234.31.186
```

里面有明显的暴力破解痕迹：

| 统计项 | 数量 |
|---|---|
| 密码错误的失败登录（Failed password） | 520 行，来自 23 个地址 |
| 失败次数最多的地址 | 183.62.140.253，286 次 |
| 尝试不存在的用户名（Invalid user） | 113 行 |
| 系统提示可能的入侵尝试（BREAK-IN ATTEMPT） | 85 行 |
| 登录成功（Accepted password） | 1 行，用户 fztu，来自 119.137.62.142 |

这份数据没有标签。适合问"哪个地址在暴力破解""有没有登录成功的"这类问题，答案可以用上表核对。

### 2.3 可选数据：APT-Hunter 检测结果样例

这是 APT-Hunter 对一批 Windows 日志跑完检测后输出的告警表。每一行是一条告警，带严重度和检测说明。

| 列名 | 含义 |
|---|---|
| `message`、`Event Description` | 检测规则的名称和说明 |
| `Severity` | 严重度：Critical 118 条、High 385 条、Medium 20 条、Low 368 条 |
| `Detection Domain` | Threat 847 条、Audit 44 条 |
| `Event ID`、`Channel`、`Computer Name` | 对应的事件类型、日志通道、主机 |
| `Original Event Log` | 原始事件的 XML |

它的主机名和主数据有重合（MSEDGEWIN10、IEWIN7、PC01.example.corp），可以和主数据对照着用。原型目前没有导入它。以后可以把它作为"告警表"加进日志库，再给智能体加一个"列出告警"的工具，对应 APT-Hunter 分诊智能体的"列线索"。

## 3 怎么用

原型代码包里已经带了前两份数据，建库脚本会把它们导入 SQLite。导入时做两件事：

- 把主数据里的每个日志文件编成一个案件，编号不透露任何信息，例如 `case_001`。
- 把 `EVTX_FileName` 和 `EVTX_Tactic` 单独存进标准答案表，智能体的工具查不到这张表。

`案件标准答案.csv` 是这张表的导出，共 250 行：`case_000` 是 SSH 日志（未标注），`case_001` 到 `case_249` 是主数据的 249 个案件。每行有案件编号、日志类型、事件数、主机、开始时间、原始文件名、ATT&CK 战术。出题和判分时用它，**不要把它的内容放进提示词或工具返回值**，否则评测没有意义。

按战术分的案件数（合计 249）：权限提升 61、横向移动 47、防御规避 36、凭据访问 35、执行 33、持久化 22、发现 10、命令与控制 5。

## 4 局限

- 主数据全是攻击样本，没有正常业务日志。能测"判断是哪类攻击"，不能测"从大量正常日志里找出攻击"。
- 主数据的各个案件互相独立，来自不同时间、不同环境，不是一次连续的入侵过程。
- 很多案件只有几条事件，信息量小，智能体可能判断不出战术。出题时优先选事件数不少于 5 条的案件，这样的案件有 134 个。
- 部分 Sysmon 事件的 `RuleName` 字段里直接写着技术名（例如 `technique_name=Credential Dumping`）。这是日志自带的检测规则名，原型没有屏蔽它。它是很强的提示，会让评测准确率偏高，评测时建议加一组屏蔽这个字段的对照。
- SSH 日志只有 2,000 行，是原始数据集的抽样。
